# Release checklist

Every user story (US), acceptance criterion (AC), business rule (BR) and non-functional
requirement (NFR) of the PRD is mapped to the evidence that verifies it (SA §11.2).
`pnpm exec tsx scripts/verify-release.ts` checks this file:

- every ID of the PRD has exactly one row;
- every evidence file exists, and each VERIFIED row cites at least one automated test or
  measuring script;
- the web and API locale bundles are a matching pair;
- every measured budget has a recorded result, and a failed measurement is never marked VERIFIED;
- the audio rights status is consistent with docs/audio-provenance.json.

The gate (the default mode) **rejects a release while any row is PENDING or GAP**. `--report`
prints the same findings without failing, for CI runs on branches. Nothing in CI publishes or
deploys. CI currently runs only when started by hand (`workflow_dispatch`); automatic push and
pull-request runs are switched off.

Statuses:

| Status   | Meaning                                                                                                                                                               |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| VERIFIED | Automated evidence exists and passes in CI (`.github/workflows/ci.yml`).                                                                                              |
| PENDING  | Needs a person: a manual review that has not been done yet, or a right or credential not yet available. It stays a release gap until someone records the result here. |
| GAP      | Measured and missed: the evidence shows the requirement is not met yet.                                                                                               |

## Reviews that only people can complete

These stay PENDING until they are done and recorded (date, reviewer, result):

1. **Audio distribution rights.** The 20 audio files are "release-unverified" (docs/audio-provenance.json,
   THIRD-PARTY-NOTICES.md). Written permission from OpenTracks for embedding them in a
   self-hostable platform is needed, or the audio must be replaced. This is a release blocker
   (TASK-114A).
2. **Accessibility with assistive technology.** Covers screen readers, IME on devices, the
   virtual keyboard and safe areas, forced colors, and switch/voice control
   (docs/accessibility-verification.md).
3. **Language review.** A native speaker must review each built-in translation (id, ja, zh-Hans,
   es, fr) in the running app.
4. **Hosted object storage.** Run the AWS S3, Cloudflare R2 and DigitalOcean Spaces smoke tests
   with real test credentials (docs/driver-verification.md).
5. **License review.** Confirm that LICENSE (Apache 2.0 with Commons Clause) and the notices match
   PRD §1.4. Nothing here is legal advice.

## Measured budgets

docs/performance-results.md records:

- the broadcast benchmark: single node PASS, two Redis nodes FAIL;
- the player bundle and cold-load budgets: FAIL on initial JS and identity-step LCP.

Each failure is a GAP with the concrete follow-up named in that document.
